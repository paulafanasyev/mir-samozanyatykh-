# Безопасная система агентов

## Что взято из исследования `MDX-Tom/gpt-5.6-instruct`

Мы **не подключаем jailbreak/unrestricted prompt**. Из репозитория берём инженерные идеи, полезные для надёжной разработки:

1. регрессионный банк реальных случаев;
2. несколько уровней проверки;
3. разделение маршрутизации, выполнения и оценки;
4. проверку артефактов, а не только текста ответа;
5. повторный цикл после обнаружения ошибки;
6. безопасный rollback и сохранение конфигурации;
7. явное разделение фактически проверенного и заявленного результата.

Источник: https://github.com/MDX-Tom/gpt-5.6-instruct

## Архитектура проекта

```text
Запрос пользователя
       |
       v
Policy Gate -----> BLOCKED (если запрос нарушает проектные границы)
       |
       v
Task Router
       |
       +--> Architecture
       +--> Coding
       +--> Security
       +--> QA
       +--> Runtime
       +--> Judge
              |
              v
       Evidence Gate
          |       |
        FAIL     PASS
          |       |
          v       v
       Retry     Done
```

## Правила

- Ни один агент не может объявить задачу готовой без evidence.
- Критические проверки: security, QA, runtime и judge.
- Provider/model selection находится отдельно от бизнес-логики оркестратора.
- Сбой одного провайдера не должен превращаться в ложный `PASS`.
- Ошибки provider policy, timeout, network, parse и model fallback должны учитываться раздельно.
- Runtime-проверка не заменяется статическим анализом.
- Для production-изменений нужен обратимый путь.
- Секреты, токены и credentials не входят в task context/evidence.

## Статусы доказательств

`verified` — реально выполненная проверка с наблюдаемым результатом.

`static` — проверка исходников/конфигурации без запуска.

`runtime-required` — проверка, которую нельзя честно считать завершённой без запуска.

`unknown` — данных недостаточно; это не PASS.

## Следующий слой

Следующим этапом подключаются реальные handlers для Coding/Security/QA/Runtime и provider adapters. Они должны возвращать структурированный `AgentResult`, а не свободный текст. Это позволит строить сравнимые regression reports и безопасно переключать провайдеры при временных сбоях.
