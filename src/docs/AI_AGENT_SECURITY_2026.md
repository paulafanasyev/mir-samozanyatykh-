# Безопасная агентная архитектура Светланы — 2026

## Что внедрено

- отдельный шлюз `app/services/agent_guard.py` перед будущими агентными действиями;
- блокировка распространённых prompt-injection атак;
- редактирование похожих на API/private keys секретов до передачи дальше;
- классификация риска `low / medium / high`;
- обязательное подтверждение для запросов, которые могут изменить внешнее состояние;
- запрет выполнения инструментов самим шлюзом: он только проверяет запрос;
- endpoint `/api/ai/guard` для web/mobile клиентов;
- endpoint `/api/ai/security-status` для диагностики;
- отдельный CI-регрессионный тест.

## Архитектурное правило

`Пользователь → AI Security Gateway → Светлана → разрешённый инструмент → проверка результата`

Модель не получает право самостоятельно решать, имеет ли пользователь доступ к данным. Авторизация должна оставаться на сервере и проверяться непосредственно инструментом/API.

## Для следующего этапа

1. подключить реальный AI Router за шлюзом;
2. описать инструменты Светланы allowlist-ом;
3. каждому инструменту назначить минимальные права;
4. все изменения данных сделать подтверждаемыми и идемпотентными;
5. писать audit event для каждой попытки tool call;
6. добавить тесты на утечки контекста, SSRF, excessive agency и unbounded consumption;
7. только после этого включать агентные действия в production.

Подход основан на актуальных рисках OWASP для LLM и агентных приложений: prompt injection, sensitive information disclosure и excessive agency должны рассматриваться как отдельный слой безопасности, а не как обычная валидация формы.
