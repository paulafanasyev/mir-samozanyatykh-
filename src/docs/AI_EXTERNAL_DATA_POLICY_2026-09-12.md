# Политика внешних AI-моделей — DLP и риск обучения на данных

Дата: 2026-09-12
Статус: IMPLEMENTED ON BRANCH / RUNTIME VERIFICATION PENDING

## Что теперь технически защищено

- `app.services.agent_guard.prepare_external()` является DLP-шлюзом перед внешним AI router.
- API/private keys и bearer-токены удаляются.
- Email и телефонные номера редактируются перед внешней моделью.
- Высокорисковые финансовые/идентификационные данные блокируются для внешнего провайдера.
- Context также проходит DLP; нельзя отправить защищённые данные только через поле context.
- При блокировке внешний router возвращает `None`, после чего `Светлана` использует локальный fallback.
- Chat log получает уже санитизированный пользовательский текст.

## Важное различие

Это **не доказательство**, что конкретный внешний AI-провайдер не использует данные для обучения, хранения, human review или иных целей.

Приложение не может честно заявлять такие свойства без проверки актуальных условий конкретного провайдера и договора/настроек аккаунта.

Поэтому техническая политика проекта строже:

`raw user data -> DLP -> sanitized content -> external provider`

а для high-risk data:

`raw user data -> DLP -> BLOCK -> local fallback`

## Почему это снижает риск «дистилляции»

Даже если внешний провайдер теоретически использует разрешённые ему запросы для улучшения моделей, приложение не должно передавать ему исходные персональные, финансовые или секретные данные пользователя.

Это ограничивает потенциальную ценность таких данных для вторичного использования и уменьшает площадь утечки.
